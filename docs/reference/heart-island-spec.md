# Heart Island 網站遊戲 — 復刻規格書

Oct 26, 2026 · @Chih Chieh, Hsieh

## 1. 概述

Heart Island 是一個「可探索的 3D 等角（isometric）小島城市」：把 14 個主題做成 14 座六角形小島，每島上的建築代表 1 個細項（共 94 個），小人沿著「協作線」在島間搬運物品，讓使用者看見主題之間的關係。它不是有輸贏的遊戲，而是「沙盒式資訊探索」＋角色扮演。

| 項目 | 原站做法 | 你的版本建議 |
| --- | --- | --- |
| 核心隱喻 | 一座城市 = 一份政見；島 = 主題；建築 = 細項；小人 = 關係 | 任何「多主題＋彼此關聯」的內容都適用，例如：診所服務島、洗腎照護島、課程地圖 |
| 規模 | 14 島 / 94 建築 / 20 條協作線 / 約 60 個走動小人 | MVP 先做 5 島 / 20 建築 / 6 條線 / 20 個小人 |
| 主要互動 | 點島 → 鏡頭飛近 → 左側詳情卡；右側清單與搜尋 | 同 |
| 遊戲感來源 | 晝夜循環、走動小人、城市日誌（即時事件流）、可自訂角色、拍照 | 先做晝夜＋小人＋日誌，角色自訂放第二階段 |
| 附加模組 | 獨立頁面的 7 題心理測驗「你是哪一種人？」 | 選配 |
| 技術 | 原生 JS + Three.js（WebGL），一份 policies.json 驅動全部內容，程式化產生幾何（無外部 3D 模型） | 同，或 React Three Fiber |

注意：原站是競選官網，請只參考機制與版面，不要沿用其品牌、標誌、人名與政見文字。

來源：[Heart Island 原站](https://puma.taipei/heart-island)（2026-10-26 實際操作與讀取 policies.json）

## 2. 畫面結構與流程

整個網站是單頁：全螢幕 3D 場景在底層，所有 UI 都是浮在上面的半透明卡片，不換頁。

### 2.1 版面區塊（桌機 1342×894 實測）

| 位置 | 元件 | 內容與行為 |
| --- | --- | --- |
| 左上 | 品牌卡 | Logo＋標題；點擊回官網首頁 |
| 上方中央（上列） | 時間切換 | 4 個圖示：清晨 06:00 / 白天 12:00 / 黃昏 18:00 / 夜晚 21:00 |
| 上方中央（下列） | 圖層工具列 | 名牌、搬運圖示、協作線、暫停動畫、鳥瞰、城市日誌（皆為開關） |
| 右上 | 導覽按鈕 | 全景（回到全景）、角色、清單、?（操作說明） |
| 右側欄（約 1/3 寬） | 索引欄 | 大標題、「14 個主題 / 94 個細項」、測驗入口卡、搜尋框、分頁「主題 / 協作關係 20」、編號清單（斜體大數字 01–14＋名稱＋細項數）；可收合、可切換全寬 / 1/3 寬 |
| 左側浮卡 | 詳情卡 | 點了島、建築或協作線才出現，右上 × 關閉 |
| 場景內 | 浮動名牌 | 島名牌「編號＋名稱」、建築名牌「圓圈編號＋名稱」、玩家頭上「我‧身分」 |

### 2.2 詳情卡三種樣式

1. **島（主題）卡**：圖示＋「POLICY 03」、標題、一句摘要、引言框（vision）、標籤列（HEART 面向、「7 個細項」、「5 條協作」）、細項清單（每列：名稱＋階段標籤如「第 1–2 年」＋ ›）、「相關協作線」膠囊。
2. **建築（細項）卡**：縮圖＋麵包屑（主題‧細項編號）、標題、標籤（面向、狀態）、「對象：…」、白話說明、**關鍵數字卡 ×2**（大字「150 公尺」＋小字說明）、重點條列、**推動時程條**（5 格：就任 / 6 個月 / 第 1–2 年 / 第 3–4 年 / 第 5–8 年，涉及的格上色）＋時程說明、相關協作線。
3. **協作線卡**：「F6」徽章、標題、證據等級標籤、「4 位市民在這條線上」、起點島 → 終點島圖、「搬運道具：書包」「角色：學童」兩格、「關聯島嶼」連結。

### 2.3 使用者流程

1. 載入 → 第一次進入跳出新手引導（「略過」「下一步 →」），可播 78 秒自動導覽（暫停 / 重播 / 離開）。
2. 全景鳥瞰 → 點島名牌或右側清單 → 鏡頭平滑飛近該島，左側開島卡。
3. 點島卡內細項或場景內建築 → 鏡頭再拉近，換成建築卡。
4. 點協作線 → 鏡頭拉遠框住相關島，只亮這條線、其他變暗。
5. 「全景」或 Esc 回到整體。
6. 支線：角色模式、城市日誌、時間切換、測驗（見第 3 節）。

## 3. 遊戲機制

沒有分數與勝負；「好玩」來自 6 個同時運作的系統。依實作優先序排列：

### 3.1 鏡頭與選取（必做）

- 等角视角固定俯角（約 45°），可拖曳平移、滾輪 / 雙指縮放；「鳥瞰」切到較高俯角。
- 三層縮放：全景 → 島 → 建築；每次轉場用 0.8–1.2 秒 easing 動畫（位置＋目標點同時內插）。
- 點擊用 raycast 挑中島或建築；名牌是 HTML 疊層，每幀把 3D 座標投影到螢幕。

### 3.2 走動小人與搬運（核心視覺）

- 約 60 個小人；每個綁一條協作線，從起點島走到終點島，頭上頂著一個「搬運圖示」，到達後停留、交接、再出發。
- 8 種角色外觀（walker）：公務員、研究員、學童、単車族、長者、家長、市民、小農。
- 15 種搬運道具（carry）：能量、時鐘、藍圖、文件夾、地球、書包、毛巾、啞鈴、卡片、書‧愛心、輔導、晶片、樹苗、菜籃、護照。
- 路徑：島上沿六角格中心連線走；島間走橋或浮橋。簡單實作：預先建「島中心→橋頭→橋頭→島中心」的 waypoint 列，小人在點間線性內插＋上下彈跳模擬走路。
- 工具列開關：「搬運圖示」隱藏道具、「協作線」顯示弧線、「暫停動畫」凍結小人與時鐘。

### 3.3 晝夜循環

- 遊戲內時鐘自動前進；上方 4 鍵可直接跳時段。燈光顏色、天空色、陰影方向隨時間內插。
- 8 個時段場景（dayCycle）：每段有開始 / 結束時間、要點亮的建築 id 清單、場景名（如 05:30–07:00 清晨登山、上學通勤、午餐…），到這時段該建築發光、出現對應人群。
- 「城市日誌」內有「播放一天」：把 24 小時壓成一段快轉。

### 3.4 城市日誌（即時事件流）

- 「日誌」分頁：LIVE 捲動列，每筆「\[出發|抵達|交接\] 07:30:09 → F1｜公務員 前往 運動政策・能量」；由小人狀態機在切換時丟出事件。可用下拉選單篩選協作線。
- 「城市概況」分頁：4 格統計（14 主題 / 94 細項 / 20 協作 / 89 位市民在路上；最後一個是即時數）、各面向的橫條、協作證據分類數、每島細項數格子。
- 另有「02 任期時間軸」（5 個階段，點了只亮該階段的建築）與「03 面向」篩選（H / E / A / R / T / 全部，點了只亮含該面向的島）。

### 3.5 我的角色（第二階段）

| 分頁 | 功能 |
| --- | --- |
| 外觀 | 名字、身分（14 選 1，切換時套用預設服裝）、預覽方向（正面 / 背面）、試衣地點、髮型等分類配件；中央放大預覽小人，腳下橙色圓弧提示可旋轉 |
| 行程 | 自由漫步 / 自動逛逛 / 點地圖指定 / 前往 14 島之一；角色在場景中真的走過去，鏡頭跟隨 |
| 拍照 | 定位到角色或偶像分身、「拍照模式」隱藏名牌與標記；用 canvas.toDataURL 匯出圖片 |

角色設定存在 localStorage，再來時還在。

### 3.6 心理測驗（選配）

- 獨立頁面，7 題、每題 4 個情境選項，頂端進度條「第 1 題 / 共 7 題」、「上一題」。
- 每個選項對應面向加分 → 最高分面向決定結果類型 → 結果頁推薦對應的島，並連回地圖定位。

## 4. 資料格式（content.json）

原站所有內容、位置、動畫腳本都由一份 policies.json（schemaVersion 3.0）驅動，程式只負責讀取與渲染。照做時先定好這份格式，內容就可以和程式分開編輯。

| 頂層鍵 | 用途 | 原站筆數 |
| --- | --- | --- |
| meta | 標題、語言、資料驗證日 | — |
| sources | 引用來源（url、檢查日、可信度） | 每主題 1 |
| islands | 島（主題），內含 buildings | 14 |
| ports | 非島的外部節點（如資料來源港口） | 3 |
| flows | 協作線 | 20 |
| quotes | 引言，供 flows 引用 | — |
| dayCycle | 時段場景 | 8 |
| termTimeline / termRules | 任期階段與規則 | 5 |
| tour | 自動導覽分鏡（78 秒） | 約 10 cue |
| renderPlan | 渲染參數（walkers: 60、六角格朝向 pointy…） | — |
| ui | 介面文字字典（i18n） | — |

精簡範例（欄位名稱與原站一致，內容為示意）：

```json
{
  "islands": [{
    "id": "transport", "number": 3,
    "name": {"zh": "交通", "en": "Transport"},
    "summary": {"zh": "一句話摘要"},
    "vision": {"zh": "引言框文字"},
    "heart": ["H", "T"],
    "axial": [-1, 5],
    "buildings": [{
      "id": "transport-school",
      "name": {"zh": "通學區"},
      "plain": {"zh": "白話說明"},
      "who": {"zh": "對象"},
      "facts": [{"zh": "重點 1"}, {"zh": "重點 2"}],
      "stats": [{"value": "150 公尺", "note": "小字說明"}],
      "phase": {"label": {"zh": "時程說明"}, "stages": ["y3-4", "y5-8"]},
      "status": {"zh": "政見"},
      "flows": ["F6"]
    }]
  }],
  "flows": [{
    "id": "F6", "from": ["transport"], "to": ["diplomacy"],
    "carry": "schoolbag", "walker": "child",
    "text": {"zh": "協作線標題"},
    "evidenceTier": "official", "bidirectional": false
  }],
  "dayCycle": [{
    "from": "07:00", "to": "09:00",
    "lights": ["transport-school"], "scene": "kids-walk",
    "label": {"zh": "通學"}
  }],
  "tour": {"durationSeconds": 78, "cues": [
    {"from": 0, "to": 3, "target": "all", "caption": {"zh": "開場字幕"}, "flows": []}
  ]}
}
```

設計重點：

- **axial 座標**：島用六角格軸向座標 \[q, r\] 排版，換算世界座標 x = size×√3×(q + r/2)、z = size×1.5×r（pointy 朝向）。改位置只要改數字。
- **flows 的 from / to 是陣列**：一條線可以一對多（原站 F1 從 1 島連到 13 島）。
- **每個文字欄位都是 {zh, en}**：先只填 zh，en 留 null，程式依 languageFallback 回退。
- **每筆資料帶 sources / evidenceTier**：介面可顯示「官方政見 / 待查證」標籤。
- stats 欄位是本規格建議加的（原站關鍵數字似乎從 facts 拆出），獨立欄位較好維護。

## 5. 視覺與音效

風格是「低多邊形（low-poly）等角小城＋米白紙感 UI＋橙色強調」，類似 Townscaper / Mini Metro 的溫和玩具感。

### 5.1 3D 場景

- 島：六角柱堆疊，岸邊米色沙灘＋淺水帶；島間橋用木棧道、橙白斷線。
- 建築：簡單方塊＋斜頂、球形樹、圖示牌（如輪椅標誌），一律程式化生成（renderPlan.geometry = original\_procedural），不用外部模型檔。
- 背景：青藍色海面、遠處低多邊形綠山與針葉林、風車、燈塔、帆船等小物件。
- 小人：大頭身比（頭約佔身高 1/3），圓柱身體＋球頭＋髮型模塊；頭上漂浮圖示氣泡。
- 燈光：平行光（太陽）＋半球環境光，色溫隨時段變；夜間建築窗戶自發光。柔和陰影（PCF soft shadows）。

### 5.2 UI

| 項目 | 規格 |
| --- | --- |
| 主色 | 橙 #DB6A41（meta theme-color） |
| 底色 | 米白紙色，卡片白底＋輕陰影＋大圓角（約 16px），浮卡半透明＋模糊背景 |
| 面向色 | 5 色編碼：H 綠、E 芥末黃、A 橙紅、R 青綠、T 紫（用於標籤圓點與橫條） |
| 中文字型 | Noto Sans TC / PingFang TC / Microsoft JhengHei |
| 大編號 | Georgia 斜體高對比賽重（01–14，橙色） |
| 小標籤 | 等寬字 ui-monospace、全大寫、加字距（如 THE POLICY INDEX、CITY LOG） |
| 名牌 | 白底膠囊＋左側橙色圓圈編號；選中時反白為深色 |
| 選中狀態 | 清單列淡橙底；工具列按鈕黑底白字 |

### 5.3 音效

原站以 Web Audio API（AudioContext）即時合成短音效，不載音檔。建議：點擊「叮」、鏡頭飛行「咕」、小人交接輕音，預設靜音，第一次使用者互動後才建立 AudioContext（瀏覽器規定）。

## 6. 技術架構與實作步驟

原站是純靜態網站：4 支原生 JS＋1 份 JSON，放在 Cloudflare 後面，沒有後端。可以直接用 Cloudflare Pages 部署。

### 6.1 檔案切分（對照原站）

| 原站檔案 | 大小 | 推測職責 | 你的對應模組 |
| --- | --- | --- | --- |
| app.js | 128 KB | Three.js 場景、島與建築生成、鏡頭、小人、面板 | scene/、walkers/、ui/ |
| heart-me.js | 107 KB | 我的角色：外觀編輯、行程、拍照、localStorage | avatar/ |
| heart-top.js | 29 KB | 上方工具列、時間、導覽、音效 | hud/、tour/ |
| heart-characters.js | 6 KB | 角色外觀定義表 | data/characters.js |
| policies.json | — | 全部內容 | data/content.json |

建議技術棧：Vite ＋ TypeScript ＋ Three.js（或 React ＋ React Three Fiber ＋ drei）；UI 用一般 DOM＋CSS 疊在 canvas 上。程式都交給 Claude Code 寫最快，一個階段一個 prompt。

### 6.2 實作階段

1. **資料先行**：寫好 content.json（5 島、每島 3–5 建築、數條 flows）與 TypeScript 型別。
2. **島與鏡頭**：依 axial 座標放六角島、海面、燈光；OrbitControls 限制俯角與縮放；完成 flyTo(target) 動畫。
3. **名牌＋右側清單＋左側詳情卡**：點島 / 建築 / 清單都呼叫同一個 select(id)；選取狀態寫進 URL hash（如 #island=transport），可分享、可上一頁。
4. **協作線與小人**：島間畫弧線（QuadraticBezierCurve3）；小人用 InstancedMesh 一次畫 60 個；狀態機 出發 → 路上 → 抵達 → 交接，每次切換丟事件。
5. **時間系統**：遊戲時鐘（例如真實 1 秒 = 遊戲 1 分鐘），驅動燈光與 dayCycle 亮燈。
6. **城市日誌**：訂閱第 4 步的事件，保留最新 100 筆；概況分頁從 content.json 即時統計。
7. **導覽與新手引導**：依 tour.cues 的時間軸依序呼叫 flyTo＋亮線＋字幕。
8. **我的角色**：外觀編輯、行程（尋路沿用第 4 步 waypoint）、拍照匯出；localStorage 以 try/catch 包住。
9. **手機版與效能**：右側欄改成底部抽屜；devicePixelRatio 上限 2；低階機關陰影、減少小人。
10. **部署**：Cloudflare Pages，設定 og:image 分享圖（1200×630）。
